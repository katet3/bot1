# JCVM IR

## Подключение в main.py

После `cap_parsing = CAPFileBuilder.build(container)`:

```python
from pathlib import Path
from jcvm_ir import IRBuilder, ReferenceResolver, methods_from_cap

ir_builder = IRBuilder(ReferenceResolver(cap_parsing))
methods = methods_from_cap(cap_parsing)
output = Path('ir_output')
output.mkdir(exist_ok=True)

for index, method in enumerate(methods):
    ir = ir_builder.build(method)
    (output / f'method_{index}.json').write_text(ir.to_json(), encoding='utf-8')
    (output / f'method_{index}.txt').write_text(ir.to_text(), encoding='utf-8')
```

Для явной проверки уже построенного CFG в примере без обработчиков:

```python
cfg = generator.build(method)
ir = ir_builder.build(method, cfg=cfg)
```

При несовпадении инструкций, разбиения или обычных рёбер выбрасывается `IRValidationError`.
Нельзя передавать прежний результат `CAPFile.to_model()` без доработки: он теряет заголовки,
сигнатуры и обработчики. `methods_from_cap()` — явный адаптер к присланному CAPFile, который
восстанавливает их из уже разобранных компонентов. Бинарный CAP модуль повторно не парсит.

## Контракт IR

Это типизированный **стековый IR**. Устранение стека, временные значения и SSA остаются
следующему `jvm_like_ir`. Короткие формы `sload_1` и `sload 1` нормализуются в `load_local<short>(1)`;
широкие и обычные формы переходов имеют единое представление. Исходные offset и mnemonic сохраняются.

- `Type`: void, boolean, byte, short, int, reference и типы массивов. Ссылочный type descriptor
  сохраняет закодированный class_ref; наследование здесь не вычисляется.
- `Operation`: нормализованная операция, тип, аргументы, ссылка, снимаемые/добавляемые значения стека,
  цели переходов и пары case/target.
- `Reference`: исходный CP index, CAP tag, AID и версия пакета, внутренний offset либо внешние tokens,
  тип поля либо сигнатура вызова. Имена API не угадываются; диспетчеризация виртуальных вызовов не выполняется.
- `Block`: операции и абстрактные типы стека на входе/выходе.
- `Edge`: тип перехода, case value, либо индекс обработчика.
- `MethodIR`: блоки, рёбра, заголовок, сигнатура, обработчики, диагностические сообщения.

Все offset инструкций, целей и границ обработчиков в IR — относительно начала байткода метода.
Диапазоны обработчиков `[start, end)`; порядок, catch_type_index и stop_bit сохраняются.
Идентичность метода включает AID, class offset и method offset, а не только token:
в example.cap четыре private метода имеют одинаковый token 255.

### Семантика для следующего преобразования

`pops` и `pushes` перечисляют логические значения снизу вверх. `int` занимает два слова JCVM,
`short` и reference — одно. Byte/boolean на стеке относятся к short; размер хранения поля/массива
сохраняется отдельно в value_type. Список args у load/store содержит индекс локальной переменной.

Арифметика — знаковая фиксированной разрядности: short 16 бит, int 32 бита; add/sub/mul сохраняют
разрядность. Следующий исполнитель/lifter обязан реализовать переполнение, деление, исключения и сдвиги
по JCVM, а не произвольную арифметику Python. `CONVERT s2b/i2b` означает сужение до byte и знаковое
расширение результата до short. `COMPARE icmp` возвращает short -1/0/1.
`FIELD_*` args различают static, this и object; implicit this не снимается со стека.
`CALL` содержит режим invoke и полную сигнатуру. Для нестатического вызова receiver снимается перед
аргументами. Нормальное ребро после вызова сохраняется: IR не предполагает, что неизвестный API
обязательно возвращает или обязательно бросает исключение.

Полная динамическая семантика не исполняется этим модулем. Это контракт представления, а не движок.

## Что проверяется

- Покрытие байткода последовательностью инструкций и размеры поддерживаемых форм.
- Совпадение исходного opcode с bytecodes в каждой позиции; корректность целевых смещений.
- Отсутствие обычного выхода за конец тела метода.
- CP tags, индексы, типы полей, сигнатуры и границы таблицы типов.
- Количество слов аргументов против method header при адаптации CAP.
- Границы locals с учётом `nargs + max_locals`, а также занимающего два слова int.
- Underflow, превышение max_stack и согласованность типов стека на слияниях, включая циклы.
- Тип возвращаемого значения против сигнатуры.
- Входной стек обработчика: одна reference; защищённые диапазоны разделяют блоки.
- `athrow` не получает обычного fallthrough; case/default не смешиваются.

Исключительные рёбра консервативные: от каждого блока защищённого диапазона к обработчикам.
Точная фильтрация по возможному типу исключения, выбор первого подходящего catch, выполнение finally
и выход исключения из метода относятся к следующему слою. Старые exception edges из CFG не используются
как источник семантики; источником является упорядоченная таблица Handler. Если исходный CFG не разделяет
границы обработчиков, передача `cfg=` завершится ошибкой; без него IR строит уточнённые блоки самостоятельно.

Это не полный Java Card bytecode verifier: типы/инициализация локальных переменных, точные классы ссылок,
иерархия, состояние uninitialized object, правила доступа и корректность внешних API не проверяются.
Недостижимые блоки сохраняются с предупреждением; их стек не анализируется.

## Поддерживаемая первая версия

Константы; load/store; pop/pop2/dup/dup2; short/int арифметика, сдвиги и преобразования;
sinc/iinc; поля instance/static/this/wide; массивы; new/newarray/anewarray;
invokevirtual/invokespecial/invokestatic; условные ветви включая `_w`; goto;
четыре switch; return/sreturn/ireturn/areturn; athrow.

Не поддерживаются `jsr/ret`, `dup_x/swap_x`, `invokeinterface`, `checkcast`, `instanceof`,
`sinc_w/iinc_w`, impdep. Они вызывают явную ошибку, а не превращаются в nop.
Адаптер к текущему linker поддерживает обычные concrete method headers; extended/abstract headers
требуют исправления upstream-парсера. Первая версия не заявляет поддержку всех CAP-файлов.

IR ожидает декодированные семантические операнды. У присланного декодера raw fallback ещё возвращает
байты для некоторых инструкций (например iipush, отрицательный iinc, часть wide/static полей).
Такие случаи нужно нормализовать в `cap_decompile`; модуль IR не скрывает их ошибки.
