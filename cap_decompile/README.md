# cap_decompile

CAPContainer и CAPFileBuilder читают бинарные компоненты и связывают методы с Descriptor.
Для typed pipeline равнозначны `jcvm_ir.methods_from_cap(cap)` и `cap.to_model()`:
после D-07 оба возвращают `list[MethodInput]` с заголовком, сигнатурой, static flag
и method-local обработчиками. Старый неполный `Method` больше не создаётся.
Смена типа результата и координат описана в руководстве подсистемы.

После D-06 linker читает обычный двухбайтовый и расширенный четырёхбайтовый
заголовок; смещение метода сохраняется до чтения заголовка относительно methods blob.
Усечённые header/body отклоняются явно. Typed pipeline по-прежнему принимает
только ordinary concrete methods: чтение extended header не включает его lowering.

После D-08 все чтения BinaryReader требуют полный диапазон и сохраняют курсор
при отказе. Декодер использует явные форматы операндов; raw fallback удалён.
Исправлены размеры lookup-switch, wide increments и stack instructions с `mn`.
Ошибки диапазона/декодирования — `BinaryParseError`, подкласс `ValueError`.

После D-09 `Applet.cap` необязателен: библиотечный пакет хранит `cap.applet is None`.
Builder сверяет наличие компонента с `Header.flags & 0x04` (ACC_APPLET), его размер
и count с Directory. Для отсутствующего компонента оба значения Directory равны
нулю. Непустое объявление без файла и повреждённый присутствующий файл — ошибки.
В `ProgramMetadata` библиотечный пакет передаётся с `applets=()`; install не создаётся.
Общий multi-package linking этим изменением не реализуется.

После D-10 сначала проверяется каталог ZIP: полные имена, дубликаты, размеры
и единственный каталог CAP-компонентов. Только затем читаются его `.cap`-файлы;
содержимое вспомогательных записей не распаковывается. Несколько каталогов
`javacard` с компонентами отклоняются явно. Короткие имена остаются публичными
ключами после проверки однозначности; исходный каталог доступен в
`container.component_directory`. Неуспешная повторная загрузка сохраняет
предыдущий полный результат, успешная — целиком заменяет его.

По умолчанию `ZipLimits` допускает ZIP до 16 MiB, до 1024 записей, до 2 MiB
на запись и до 16 MiB суммарного заявленного распакованного размера. Ограничения
учитывают все записи, включая вспомогательные. Это политика анализатора;
настройка и точные границы описаны в [руководстве подсистемы](../docs/modules/cap_decompile.md).

Проверки из корня проекта (99 тестов D-06–D-10, без angr/pysoot):

```powershell
.\.venv-angr10\Scripts\python.exe -m unittest discover -s cap_decompile/tests -p "test_*.py" -v
```
