# Как запустить символьное исполнение своего Java Card апплета

Отдельное руководство для пользователей **cap2soot**. Версия документа: 11 ноября 2026 года.

Результат работы по этому руководству — воспроизводимый эксперимент: ваш CAP, таблица символов, описание входов и цели, найденные APDU и отчёт о том, завершён ли поиск. Имена классов, AID, смещения методов и протокол задаются для вашей сборки.

Руководство соответствует интерфейсам проекта с исправлениями D-01–D-08, `JavaCardSession` и профилями API из `angr_integration/javacard_api.py` и `angr_integration/symdemo_api.py`. Контрольные прогоны выполнены в Linux с Python 3.12.14; команды для пользователя приведены для PowerShell. Отдельного прогона в Windows и на физической карте не было.

**Граница применимости.** Среда исполняет поддержанное подмножество Java Card. Для своего апплета нужно проверить байткод и внешние API. Если нужного поведения в модели нет, сначала расширяется среда. Переименование CAP или заполнение `symbols.json` само по себе такую поддержку не добавляет.

В приложениях A и B приведены два полных Python-файла. Это новые универсальные шаблоны данного руководства: сохраните их рядом с `main.py`. Все настройки конкретной сборки находятся в JSON, а не внутри этих файлов.

## 1. Что делает символьное исполнение

При обычном запуске вы выбираете байты запроса и наблюдаете результат. При символьном запуске часть байтов остаётся неизвестной. Среда идёт по программе и собирает условия, при которых можно пройти каждую ветку. Решатель ограничений подбирает значения неизвестных, удовлетворяющие этим условиям.

Например, код проверяет два входных числа: их сумма должна быть 10, а разность — 2. Вместо ручного перебора решатель найдёт `6` и `4`. В настоящем эксперименте условия берутся из исполняемого CAP. Их не нужно заранее переписывать в Python в качестве ответа.

| Термин | Простое объяснение |
| --- | --- |
| Символьный байт | Переменная, которая может принимать значения `00`–`FF` |
| Состояние | Текущая позиция в программе, значения переменных, память апплета и накопленные условия |
| Путь | Одна последовательность выбранных ветвей |
| Ограничения пути | Условия, необходимые для прохождения этих ветвей |
| Решатель, solver | Компонент, который проверяет совместимость условий и находит значения |
| Свидетель, witness | Один конкретный набор входных байтов, подходящий найденному пути |
| Модель API | Реализация поведения внешнего Java Card метода внутри среды анализа |

Сначала сформулируйте вопрос. Например: «Какие DATA приведут к вызову `acceptRequest()` после успешной инициализации?» или «Может ли команда завершиться с SW `9000` без предварительного разрешения?» Вопрос «выполнить весь апплет символьно» слишком широк: нужно определить вход, исходное состояние и наблюдаемую цель.

Основной маршрут ниже ищет **вход в выбранный метод из `process(APDU)`**. Отдельно разобраны поиск по SW и прямой вызов вычислительного метода.

## 2. Что подготовить

| Данные | Для чего нужны | Как участвуют в запуске |
| --- | --- | --- |
| `applet.cap` | Байткод, классы, подписи, импорты и сведения об установке | Главный исполняемый вход |
| Java-исходники той же сборки | Понять протокол и выбрать интересующий участок | Читает пользователь; среда не исполняет Java-файл |
| `applet.jca` той же сборки | Сопоставить инструкции, имена, токены и методы | Используется при подготовке символов и проверке адресов |
| `applet.exp` и экспортные данные импортируемых API | Проверить публичные токены, типы и версии пакетов | В этом маршруте автоматически не импортируются |
| `symbols.json` | Связать числовые идентификаторы CAP с именами | Читает конвейер |
| Профиль API | Определить поведение внешних вызовов | Подключает загрузчик |
| `analysis.json` | Задать команду, неизвестные байты, цель и предел поиска | Читает шаблон запуска |

EXP не содержит всех частных методов апплета. По одному EXP нельзя восстановить все имена. Отсутствующие данные нельзя заменять предположением, что порядковый номер метода равен его токену или смещению.

Сведения о версии и AID берите из **фактической сборки**. Java-комментарий или название папки могут устареть. AID пакета и AID установленного апплета — разные сущности: ключи символов используют пакет, регистрация экземпляра — апплет.

Разместите файлы следующим образом:

| Путь от корня проекта | Содержимое |
| --- | --- |
| `main.py` | Существующий конвейер проекта |
| `inspect_applet.py` | Код из приложения A |
| `applet_lab.py` | Код из приложения B |
| `examples/my_applet/applet.cap` | Ваша сборка |
| `examples/my_applet/applet.java`, `.jca`, `.exp` | Сопроводительные файлы вашей сборки |
| `examples/my_applet/symbols.json` | Подготовленная таблица символов |
| `examples/my_applet/analysis.json` | Ваш эксперимент |
| `outputs/my_applet/` | Результаты запуска |

Имена `my_applet` и `applet.cap` условные; их можно заменить согласованно во всех путях. Для исходников с несколькими классами сохраняйте исходную структуру пакетов.

## 3. Подготовить окружение

Откройте PowerShell **в каталоге, где лежит `main.py`**. Проверенный набор зависимостей: Python 3.12.14, angr `10.0.4.post1`, cle `10.0.4`, archinfo `10.0.4`, pysoot revision `16ab55db71a162efea3d44251fb93893140bbef2`.

Если рабочее окружение уже есть, достаточно проверки:

```powershell
.\.venv-angr10\Scripts\python.exe --version
.\.venv-angr10\Scripts\python.exe -c "from angr_integration.dependencies import load_dependencies; d=load_dependencies(); print(d.angr.__version__)"
```

Если окружения нет, создайте его с Python 3.12 и установите зависимости проекта. Для установки pysoot из закреплённой Git-ревизии нужен доступный `git`:

```powershell
py -3.12 -m venv .venv-angr10
.\.venv-angr10\Scripts\python.exe -m pip install -r requirements-angr.txt
```

Если выбираете профиль `name1`, установите также его зависимость для конкретных DES-вычислений:

```powershell
.\.venv-angr10\Scripts\python.exe -m pip install -r requirements-javacard.txt
```

Не заменяйте закреплённый pysoot произвольной версией из PyPI. Загрузчик проверяет совместимость зависимостей. В используемой сборке Claripy доступен через `from angr import claripy` или `loaded.dependencies.claripy`.

Активация окружения не обязательна, поскольку команды явно указывают Python. В Linux аналогичный путь обычно `.venv-angr10/bin/python`. Параметр `--no-png` в командах ниже отключает отрисовку PNG; Graphviz для этих запусков не нужен.

## 4. Получить идентификаторы своей сборки

Сохраните код приложения A как `inspect_applet.py` и выполните:

```powershell
.\.venv-angr10\Scripts\python.exe inspect_applet.py examples/my_applet/applet.cap --output outputs/my_applet/inventory.json --symbols-template examples/my_applet/symbols.template.json
```

Получатся два файла:

| Файл | Что смотреть |
| --- | --- |
| `inventory.json` | `cap_sha256`, версия CAP, AID и версия пакета, упорядоченные импорты, апплеты, методы, constant pool и descriptor |
| `symbols.template.json` | Реальные ключи внутренних методов и классов; вместо имён пока стоят `REPLACE_...` |

Скрипт **не угадывает имена** по исходному Java. Скопируйте шаблон в `symbols.json` один раз и заполните его. Если файл шаблона уже существует, инспектор откажется перезаписывать его: для повторной инвентаризации задайте другое имя.

Ключ метода имеет вид:

```text
<AID_ПАКЕТА>@<MAJOR>.<MINOR>:internal:t6:o<СМЕЩЕНИЕ_МЕТОДА>
```

Угловые скобки здесь обозначают заменяемые части. Для запуска копируйте **готовый ключ из своего `inventory.json`**, не набирайте его по этой схеме вручную.

| Часть ключа | Значение |
| --- | --- |
| AID и версия | Идентичность пакета |
| `internal` | Метод принадлежит анализируемому пакету |
| `t6` | Вид внутренней CAP-ссылки в данном представлении; не признак Java `static` |
| `o...` | Смещение заголовка метода относительно info-части Method component |

Последнее число не равно номеру строки Java и не равно смещению инструкции внутри метода. После пересборки оно может измениться. Токен частного метода также нельзя считать уникальным: значение `255` может повторяться.

## 5. Заполнить symbols.json

### 5.1. Что заполняется вручную

Сначала сопоставьте каждый метод из `inventory.json` с методом в JCA. Сверяйте класс, параметры, возвращаемый тип, `static`, размер байткода и характерные инструкции/вызовы. Для похожих частных методов одного размера дополнительно проверяйте места вызова и тело. Порядка строк в двух файлах недостаточно.

| Раздел JSON | Действие пользователя |
| --- | --- |
| `package_aid`, `package_version` | Оставить значения из CAP |
| `imports` | Оставить фактические AID/версии и **исходный порядок** из CAP |
| `class_names` | Подставить полные имена внутренних классов и добавить используемые внешние классы |
| `method_names` | Подставить имена внутренних методов и добавить используемые внешние методы |
| `field_names` | Добавить корректные имена полей при необходимости; внешние используемые поля должны быть разрешены |
| `catch_types` | При наличии обработчиков сопоставить их ссылки на классы исключений; это не включает исполнение обработчиков |
| `interface_signatures` | Добавить недостающие подписи интерфейсных вызовов |

Конструктор называется `<init>`. Правильно сопоставьте `install` и `process`, включая тип параметра `javacard.framework.APDU`. Сеанс находит `process(APDU)` зарегистрированного объекта по этой подписи. Если вместо имени оставить `method_...`, автоматический вход через сеанс может не найти обработчик команды.

В шаблоне нельзя оставлять имена `REPLACE_...`: `applet_lab.py` их проверяет. Внутренние поля без явно заданных имён могут получать технические имена от конвейера; если задаёте имена вручную, обеспечьте согласованность всех ссылок на одно поле.

### 5.2. Как понять внешнюю ссылку

Внешний ключ имеет форму:

```text
<AID_ИМПОРТА>@<MAJOR>.<MINOR>:c<ТОКЕН_КЛАССА>:t<ВИД_ССЫЛКИ>:m<ТОКЕН_МЕТОДА>
```

Для внешней ссылки из constant pool:

1. Найдите её `package_token` и соответствующий элемент `imports` по индексу.
2. Возьмите AID и версию именно этого импортируемого пакета.
3. Проверьте `class_token`, `tag` и токен члена по JCA/экспортным данным этой версии API.
4. Добавьте имя внешнего класса в `class_names` и имя метода в `method_names`.

`index` записи constant pool — номер записи в таблице. Он **не является** токеном метода. Для `invokeinterface` токен метода задаётся также инструкцией; записи class reference самой по себе недостаточно. Используйте ключ, который конвейер сообщает для конкретного вызова.

Можно перенести внешние записи из уже проверенного `symbols.json` другого апплета, если AID, версии, токены и подписи совпадают. Внутренние ключи другого CAP переносить нельзя.

### 5.3. Если не хватает interface_signatures

Ошибка `Missing explicit interface signature: ...` означает, что конвейеру не хватает типов параметров/результата интерфейсного вызова. Добавьте в `interface_signatures` запись под **точным ключом из ошибки**.

Пример формы записи для метода с параметрами `byte[]`, `short` и результатом `void`:

```json
{
  "REPLACE_WITH_KEY_FROM_ERROR": {
    "parameters": [{"kind": "byte[]"}, {"kind": "short"}],
    "returns": {"kind": "void"}
  }
}
```

Это содержимое раздела `interface_signatures`, а не целый `symbols.json`. Подпись должна соответствовать реальному методу; приведённые типы нельзя копировать для другого вызова. Для ссылочных типов требуется согласованная с CAP ссылка `class_ref` в представлении типов проекта.

**Имена отвечают на вопрос «что вызвано», API-модель — «что вызов делает».** Исправление имени или подписи не реализует отсутствующий метод.

## 6. Выбрать API-профиль

Профиль задаёт точные внешние методы, которые среда умеет исполнять. В проверенной версии загрузчика доступны `name1` и `symdemo`. Названия исторические: профиль можно применить к другому апплету, если совпадает используемый набор API и его семантика. Совпадения имени Java-метода недостаточно — учитываются версия пакета, токены и подпись.

| Значение `api_profile` | Привязки | Что покрывает |
| --- | --- | --- |
| `symdemo` | Ограниченный набор `javacard.framework` версии пакета `1.6` | Семь lifecycle/APDU/ISOException вызовов из таблицы ниже |
| `name1` | Ограниченные наборы framework, security и crypto версии пакетов `1.5` | Те же основные вызовы с привязками 1.5; отдельные операции транзакций/копирования и конкретного DES/TDES |
| `null` | Без API-профиля | Загрузка и изолированные поддержанные методы; `JavaCardSession` требует профиль |

Версия пакета `1.5`/`1.6` в Import.cap не равна номеру платформы Java Card `3.x`. Нельзя заменить версию в символах, чтобы «подошёл» профиль: она является частью идентичности реальной ссылки.

Базовые семь вызовов:

| Вызов | Поведение модели |
| --- | --- |
| `Applet.<init>()` | Участие в создании экземпляра при установке |
| `Applet.register(byte[], short, byte)` | Регистрация экземпляра с переданным AID |
| `Applet.selectingApplet()` | Возвращение заданного сценарием флага выбора |
| `APDU.getBuffer()` | Ссылка на моделируемый APDU-буфер |
| `APDU.setIncomingAndReceive()` | Первый приём данных с заданной длиной |
| `APDU.setOutgoingAndSend(short, short)` | Формирование байтов ответа |
| `ISOException.throwIt(short)` | Завершение команды с указанным SW |

Перегрузка `Applet.register()` без параметров — другой метод; базовые профили выше её не включают. Они также не предоставляют автоматически `OwnerPIN`, `APDU.receiveBytes()` и любой другой метод framework.

Точный список выбранного профиля попадёт в `loader/load_report.json`, поле `api_models`. Детали и ограничения поведения находятся в исходниках моделей. У `name1` DES-операция требует однозначно определённых байтов криптографического входа; символическая криптограмма не вычисляется автоматически.

Если профиль не подходит, переходите к разделу 15. Это задача расширения модели среды, а не дополнительный параметр CLI.

## 7. Проверить преобразование CAP

После заполнения символов сначала проверьте конвейер без angr:

```powershell
.\.venv-angr10\Scripts\python.exe main.py --cap examples/my_applet/applet.cap --symbols examples/my_applet/symbols.json --output-root outputs/my_applet/pipeline --no-pysoot --no-png --quiet
```

Эта команда строит CFG и промежуточные представления до Soot IR. Успех означает, что данные прошли этот этап преобразования. Он не доказывает готовность программы к исполнению.

При диагностике полезны следующие каталоги:

| Каталог результата `main.py` | Назначение |
| --- | --- |
| `cfg_output` | Блоки и переходы между ними |
| `ir_output` | Нормализованное представление JCVM |
| `jvm_ir_output` | Явные значения и операции после устранения неявного стека |
| `soot_output` | Представление Soot и разрешённые ссылки |
| `pysoot_output` | Объекты/метаданные адаптера при включённом pysoot |
| `angr_output` | Отчёт загрузчика и адреса при включённом angr |

Последние два каталога создаются при соответствующих включённых этапах. Не смешивайте старые результаты другой сборки с новым экспериментом.

## 8. Описать эксперимент в analysis.json

Сохраните приложение B как `applet_lab.py`. Создайте `examples/my_applet/analysis.json` по следующей форме:

```json
{
  "cap": "applet.cap",
  "symbols": "symbols.json",
  "api_profile": "symdemo",
  "output": "../../outputs/my_applet/execution",
  "install_steps": 500,
  "max_steps": 500,
  "setup": [],
  "baseline": {
    "cla": "80",
    "ins": "10",
    "p1": "00",
    "p2": "00",
    "data": "00 00"
  },
  "input": {
    "cla": "80",
    "ins": "10",
    "p1": "00",
    "p2": "00",
    "data": "* *",
    "selecting": false
  },
  "target_key": "REPLACE_WITH_YOUR_METHOD_KEY"
}
```

**Перед запуском замените протокол команды, профиль и `target_key` на свои.** `80 10` и два байта данных здесь иллюстрируют формат, а не являются универсальной Java Card командой. `baseline` должен содержать известный вам конкретный запрос для проверки среды.

Все пути внутри JSON считаются **от каталога самого JSON**. Поэтому `cap: "applet.cap"` указывает на CAP рядом с конфигурацией, а `../../outputs/...` — на каталог результатов в корне проекта. В JSON удобнее использовать `/`; для `\` требуется JSON-экранирование.

Рекомендуется также добавить поле `cap_sha256` со строкой из `inventory.json`. Тогда другая сборка не будет случайно запущена со старыми символами и целью. После пересборки сначала пересмотрите привязки, затем обновите хеш.

### 8.1. Какие байты оставить неизвестными

| Запись | Значение в шаблоне |
| --- | --- |
| `"cla": "80"` | CLA фиксирован: `0x80` |
| `"ins": "*"` | Рассматриваются все значения INS |
| `"p1": "*"` | P1 символический |
| `"data": "* * 01 00"` | Четыре байта DATA: два неизвестных и два фиксированных |
| `"data": ""` | Нет входных DATA |
| `"selecting": false` | Обычный вызов process; `selectingApplet()` возвращает false |
| `"receive_length": 2` | Первый приём возвращает 2; число должно быть от 0 до длины DATA |

Байты задаются шестнадцатеричными **строками**, например `"20"`. Это `0x20`, а не десятичное 20. Звёздочка разрешена только в режиме `find`, в разделе `input`. В `baseline` и `setup` все байты конкретные.

Для первого эксперимента обычно удобно зафиксировать CLA, INS и формат команды, оставив неизвестными проверяемые данные. Так вопрос становится точным: «Какие данные подходят этой команде?» Если сделать неизвестным INS, поиск будет затрагивать и другие обработчики, включая их неподдерживаемые операции.

### 8.2. Длина, Lc, приём и Le

В этом шаблоне Lc автоматически равен числу токенов в `data`. Строка `"* *"` означает **ровно два** входных байта, а не произвольную длину. Допускается до 255 байтов. Для разных длин создайте отдельные конфигурации и выполните отдельные эксперименты.

По умолчанию `receive_length` равен длине DATA. Он задаёт размер первого приёма моделью `setIncomingAndReceive()`. Это отдельная характеристика среды: наличие Lc не гарантирует, что первый приём реальной команды вернёт столько же байтов. Сценарии последующих приёмов требуют соответствующей API-модели.

Отчёт содержит `packet_without_le_hex`: логическую последовательность `CLA INS P1 P2 Lc DATA`, использованную моделью. Это не универсальная готовая транспортная команда для считывателя. Le в сценарии не моделируется; если он нужен на карте, сформируйте транспортную APDU по протоколу апплета. При отсутствии DATA учитывайте различие форм APDU без Lc/с Le. Не добавляйте произвольный завершающий байт по аналогии с чужим примером.

## 9. Загрузить программу и проверить готовность

```powershell
.\.venv-angr10\Scripts\python.exe applet_lab.py load examples/my_applet/analysis.json
```

Откройте `outputs/my_applet/execution/loader/load_report.txt`. На этом шаге `target_key` ещё не используется, поэтому его можно выбрать после просмотра списка методов.

Проверьте:

1. `Unresolved symbols: 0` — внешние ссылки имеют необходимые имена/типы.
2. Нужные классы и сигнатуры соответствуют вашей сборке.
3. `install` и `process` готовы к исполнению в выбранном профиле.
4. Для интересующего метода нет непонятных `execution_issues`.

`Execution ready` относится к возможностям реализации. Оно не означает, что найден путь к методу. Проверка рассматривает потенциальные вызовы транзитивно: неподдерживаемый метод даже в другой ветке `process` может заблокировать подготовку состояния. Фиксированный INS не всегда устраняет такой статический блокер.

Фраза `Loaded only` и код завершения 0 для режима `load` означают только успешную загрузку. `install` и `process` в этом режиме ещё не запускались.

Ту же загрузку можно выполнить через существующий `main.py`, убрав `--no-pysoot` и добавив `--javacard-profile` с подходящим значением. `main.py` также не начинает исполнение автоматически. `--angr-entry` задаёт адрес входа загрузчика, а не условие поиска.

## 10. Выполнить известную конкретную команду

```powershell
.\.venv-angr10\Scripts\python.exe applet_lab.py concrete examples/my_applet/analysis.json
```

Шаблон создаёт сеанс, выполняет настоящий `install` из CAP, подготавливает APDU по разделу `baseline` и исполняет `process`. Отчёт — `outputs/my_applet/execution/concrete.json`.

Сравните `one_model.sw` и `one_model.response_hex` с ожидаемым поведением **вашего** апплета. Режим `concrete` показывает ответ и полноту исполнения, но не знает спецификацию апплета и автоматически не утверждает, что SW должен быть `9000`.

| Результат | Что он означает |
| --- | --- |
| Есть `completed`, `active=0`, `errors=[]` | Команда завершилась в модели |
| SW `9000` | Нормальное завершение без другого установленного SW; прикладной смысл определяется вашим протоколом |
| Другой SW, например `6700` | Возможный штатный отказ апплета; сравните с его кодом |
| Непустой `errors` | Ошибка/ограничение среды, которое нельзя считать обычным SW |
| `active>0` | Некоторым путям не хватило бюджета шагов |

`ISOException.throwIt()` с отказным SW — наблюдаемый исход команды. Это отличается от `errored`, куда попадают ошибки исполнения и ограничения модели.

### 10.1. Если нужна последовательность команд

После новой установки состояние апплета может отличаться от рабочего. Например, сначала требуется загрузить параметры или разрешить операцию. Перечислите **конкретные** подготовительные команды в `setup`:

```json
"setup": [
  {
    "cla": "80",
    "ins": "01",
    "p1": "00",
    "p2": "00",
    "data": "01 02",
    "expected_sw": "9000"
  }
]
```

Это пример структуры; байты заменяются вашим протоколом. Для каждой подготовительной команды `expected_sw` обязателен. Шаблон требует единственного завершённого состояния без ошибок и проверяет SW, после чего сохраняет состояние через `session.choose(end)`.

Режимы `concrete` и `find` каждый раз начинают с новой установки и одного и того же `setup`. Результат предыдущего запуска CLI не переносится в следующий автоматически. Символьные последовательности с несколькими возможными состояниями после подготовительной команды требуют отдельного сценария, который хранит и продолжает каждый нужный путь.

### 10.2. Что делает установка в текущем сеансе

`JavaCardSession.install()` передаёт в апплет массив: длина AID, AID, нулевая длина управляющих данных и нулевая длина данных апплета. AID берётся из Applet.cap. Затем выполняются код установки и конструктор, проверяется регистрация и находится `process(APDU)`.

Сеанс рассчитан на один апплет в CAP и один логический канал. Если ваш install требует собственные установочные параметры, понадобится расширить подготовку install-данных в harness. Поля `data` команд `setup` не являются установочными параметрами. Физические операции GlobalPlatform и выбор апплета на карте этот вызов не выполняет.

## 11. Выбрать цель и выполнить поиск

Найдите в `loader/load_report.json` метод, вход в который хотите проверить. Скопируйте его `key` в `target_key` конфигурации. Проверьте полную сигнатуру: одно имя может соответствовать нескольким перегрузкам.

```powershell
.\.venv-angr10\Scripts\python.exe applet_lab.py find examples/my_applet/analysis.json
```

Шаблон выполняет следующий сценарий:

1. Загружает CAP и устанавливает апплет.
2. Выполняет конкретный `setup`, если он задан.
3. Создаёт APDU: звёздочки становятся независимыми восьмибитными переменными.
4. Начинает исполнение с `process(APDU)`.
5. При входе в целевой метод сохраняет состояние и условия пути.
6. Продолжает исследовать остальные пути в пределах бюджета.
7. Для каждого найденного состояния получает один цельный пакет байтов.
8. Продолжает найденное символьное состояние до конца команды.
9. Повторно запускает конкретный пакет из того же состояния после install/setup и отдельно проверяет достижение цели.

Итог находится в `outputs/my_applet/execution/find.json`. Подробности загрузки — в подкаталоге `loader`.

### 11.1. Как читать результат

| Поле | Значение |
| --- | --- |
| `result.verdict = reached` | Хотя бы один исследованный путь вошёл в целевой метод |
| `result.verdict = unreachable_in_model` | Цель не найдена, все пути поиска завершены без зарегистрированных блокеров |
| `result.verdict = unknown` | Цель не найдена, но поиск неполон: есть активные состояния, ошибки или необработанные stashes |
| `result.search.complete` | Завершён ли поиск **до первого попадания в цель на каждом пути** |
| `result.search.found` | Количество найденных состояний, не количество подходящих APDU |
| `result.paths[i].constraints` | Накопленные условия i-го найденного пути |
| `result.paths[i].packet_without_le_hex` | Один подходящий конкретный пакет для этого пути |
| `result.paths[i].continuation` | Возможные окончания команды после достигнутой цели |
| `result.paths[i].replay.target_reached` | Попал ли конкретный пакет в цель при повторном запуске |
| `result.paths[i].replay.completed` | Ответы полного конкретного повторного запуска |

**`reached` и `complete` отвечают на разные вопросы.** Цель могла быть найдена, а другая ветка — остановиться на неподдерживаемой операции. Тогда `reached` остаётся обоснованным свидетельством, но полного перечисления условий ещё нет. Все ошибки нужно сохранить в результате эксперимента.

Достижение входа в метод не означает его успешного выполнения. После входа он может вернуть отказной SW или встретить ошибку модели. Для успеха команды проверяйте `continuation` и `replay`.

Код завершения шаблона `0` в режиме `find` означает, что поиск и дополнительные прогоны завершились без отмеченных проблем; итог может быть как `reached`, так и `unreachable_in_model`. Код `2` означает неполноту/ошибки или неуспешную проверку повторного достижения. Ошибки конфигурации/загрузки могут закончиться исключением до записи нового отчёта; старый файл не следует принимать за новый результат.

### 11.2. Один пакет и все подходящие значения

Один witness — один пример. Путь может описывать миллионы входов. Если найдено несколько состояний, полное условие достижения — объединение их условий, то есть логическое «ИЛИ». Это полное условие только для завершённого поиска в зафиксированном контексте.

Отдельные минимумы/максимумы переменных не описывают зависимости между ними. Также нельзя собирать APDU из независимых вызовов `solver.eval()` для каждого байта: между байтами могут быть отношения. Шаблон получает пакет как одно выражение `Concat(...)`.

В `completed` поле `one_model` содержит совместно согласованные вход, ответ и SW из **одного** решения. Если ответ зависит от символических данных, это лишь пример ответа. Поля `response_expressions`, `sw_expression` сохраняют выражения, а `sw_is_unique` показывает, одинаков ли SW для всех решений этого конечного состояния.

Продолжение остаётся символическим: `continuation.completed[*].one_model` может содержать другой подходящий вход, чем минимальный witness у найденного пути. Для результата именно выбранного witness смотрите `replay`.

### 11.3. Бюджет поиска

`max_steps` ограничивает число раундов `SimulationManager.step()`. Это не число APDU, не число строк Java и не время в секундах. Один раунд может продвинуть несколько активных состояний. Для установки используется отдельный `install_steps`. Продолжения и повторные запуски также ограничены своим запуском с `max_steps`.

При `active>0` можно увеличить бюджет или уточнить область входов. Изменение области входов меняет исследуемый вопрос: это нужно записать в конфигурации. Увеличение бюджета не исправляет отсутствующую API-модель. В этом шаблоне нет отдельного ограничения по времени и памяти; большой поиск может потребовать дополнительных ограничений ресурсов.

## 12. Как связать цель со строкой Java

Среда работает с адресами представления CAP/Soot. Универсального параметра `--java-line 66` в текущем маршруте нет. Один Java-оператор может соответствовать нескольким операциям, а новая сборка меняет смещения.

| Координата | Что обозначает |
| --- | --- |
| Строка Java | Место в конкретном исходном файле |
| Method offset в ключе | Заголовок метода в Method component |
| `cap_offset` | Смещение инструкции внутри байткода метода |
| Unit label | Метка операции Soot |
| Soot address | Метод, блок и позиция операции в представлении angr |

Для цели «дойти до вызова метода» обычно достаточно искать вход в вызываемый метод. Если его вызывают из нескольких мест, такой поиск объединит все эти места. Для одного конкретного места вызова нужно дополнительно проверять вызывающий контекст или остановиться на соответствующей операции caller.

Сопоставление проверяется через JCA, отчёты IR и `loader/addresses.json`. В Python доступны:

```python
loaded.method_address(method_key)
loaded.address_for_label(method_key, unit_label)
loaded.addresses_for_offset(method_key, cap_offset)
loaded.source_location(address)
```

При поиске произвольной операции внутри блока простой цикл из приложения B может её не увидеть: обычный шаг движка способен выполнить несколько операций до следующего наблюдаемого адреса. Нужен сценарий с управлением шагом/точкой останова и проверкой фактического попадания. Не подменяйте это сравнением с номером Java-строки.

Если исходники можно менять, отдельный метод-маркер в интересующей ветке часто делает первый эксперимент проще. После его добавления нужно пересобрать CAP, обновить символы, цель и хеш. Такой эксперимент относится уже к изменённой сборке.

## 13. Другие цели анализа

### 13.1. Найти вход, возвращающий заданный SW

Когда цель определяется ответом, можно исполнять команду до завершения и отбирать конечные состояния по SW. Ниже код для отдельного сценария, выполняемого рядом с `main.py` и двумя шаблонами. Конфигурация и поддержка API готовятся тем же способом:

```python
import json
from pathlib import Path
from applet_lab import load_program, install_and_prepare, prepare, bits

config_path = Path('examples/my_applet/analysis.json').resolve()
config = json.loads(config_path.read_text(encoding='utf-8-sig'))
loaded, _ = load_program(config, config_path.parent)
session, _ = install_and_prepare(loaded, config)
state, packet = prepare(session, config['input'], symbolic=True)
result = session.run(state, max_steps=config['max_steps'])
c = loaded.dependencies.claripy
wanted_sw = 0x9000  # Замените на свой наблюдаемый результат.
found = False
for end in result.completed:
    sw = bits(end.javacard.status, 16, c)
    if end.solver.satisfiable(extra_constraints=[sw == wanted_sw]):
        hit = end.copy()
        hit.solver.add(sw == wanted_sw)
        witness = hit.solver.eval(packet, cast_to=bytes)
        print(witness.hex(' ').upper())
        found = True
print('found:', found, 'active:', len(result.active), 'errors:', len(result.errored))
```

Отбор выполняется **после исполнения** и использует полученный SW. Если ничего не найдено, а есть `active` или `errored`, вывод о недостижимости делать нельзя. Для прикладного успеха может понадобиться также проверить байты ответа или состояние памяти: некоторые апплеты возвращают `9000` и для служебных ветвей. Найденный вход повторите конкретно из того же состояния setup.

### 13.2. Исследовать отдельный вычислительный метод

Для статического метода, например с одним параметром `short`, можно подготовить состояние напрямую:

```python
from angr_integration import SymbolicArgument

# loaded уже построен конвейером; key взят из отчёта вашей сборки.
state = loaded.create_call_state(key, [SymbolicArgument('x')])
x = state.globals['cap2soot.inputs'][0]
manager = loaded.project.factory.simgr(state).run(n=500)
print('completed:', len(manager.deadended),
      'active:', len(manager.active), 'errors:', len(manager.errored))
for end in manager.deadended:
    print('one input:', end.solver.eval(x))
    print('constraints:', [str(v) for v in end.solver.constraints])
```

Этот фрагмент предполагает **статический метод с одним примитивным аргументом**, готовый к исполнению и не требующий неподготовленного состояния. `SymbolicArgument` создаёт переменную нужной ширины по подписи. Если создавать BV вручную, `byte` требует 8 бит, `short` — 16, `int` — 32, `boolean` — 1; внутреннее расширение выполнит адаптер.

Для instance-метода нужны реальный `receiver` и `base_state`, содержащий его кучу. Для ссылочных аргументов нужны корректные объекты/массивы. Передача `None` вместо APDU не создаёт окружение апплета.

Результат прямого вызова относится к заданным аргументам и памяти. Он сам по себе не доказывает, что такое состояние достижимо через последовательность APDU.

## 14. Ограничения, которые нужно учитывать при переносе

| Область | Ограничение текущего маршрута |
| --- | --- |
| CAP | Проверенные примеры используют формат 2.2; ряд компонентов явно ограничен 2.1/2.2. Наличие определения версии 2.3 в коде не означает полной поддержки |
| Метод | Расширенные заголовки могут быть разобраны нижним уровнем, но typed-адаптер методов пока их отклоняет |
| Контейнер | Один пакет; библиотечный CAP без Applet.cap и несколько пакетов в контейнере не поддерживаются этим маршрутом |
| Сеанс | Один апплет, один канал, короткие APDU, конкретные длины и параметры приёма |
| API | Только явно зарегистрированные вызовы выбранного профиля |
| Исключения | Модель ISOException завершает команду; общий переход в Java/CAP exception handlers не реализован |
| Арифметика | Поддержка преобразования операции в IR не гарантирует её исполнение; readiness отдельно проверяет операции. В текущем списке проверенных binop есть add/sub/mul/and/or/xor/rem |
| Память | Объекты и instance-поля принадлежат отдельному пути; длина выделяемого массива должна определяться однозначно. Индексы примитивных массивов могут быть символическими при доказанной допустимости |
| Возможная ошибка доступа | Может остановить состояние диагностикой; среда не должна молча исключать опасные значения |
| Инициализация классов | Автоматическое общее выполнение `<clinit>` и модель mutable static storage не предоставлены как полная Java-среда |
| Криптография | Наличие модели DES не даёт произвольное символьное вычисление криптографии |
| JCRE | Полный firewall, общая многоапплетная среда, GlobalPlatform и восстановление после потери питания не моделируются |
| Слияние путей | Общее merge/widen состояния Java Card не реализовано |

Нельзя переносить вывод «не достижимо» за пределы модели. Корректная формулировка: «В этой сборке, после такого setup, при указанных длине, флаге выбора и диапазонах входов цель не достижима в реализованной модели; поиск завершён без ошибок».

Перед переносом свидетеля на карту воспроизведите её исходное состояние и подготовительную последовательность. Совпадение на карте — отдельная проверка точности модели, особенно для транзакций, приёма APDU и внешних API.

## 15. Что делать, если нужного API нет

Сообщение `Missing method/API model` — указание на конкретный недостающий контракт. Добавление имени в `symbols.json` решает только идентификацию.

Работа разработчика среды включает:

1. Проверить точный ключ вызова, версию API, владельца, параметры и возвращаемый тип по сборке и экспортным данным.
2. Описать класс и иерархию, если они нужны для типов/dispatch, через метаданные адаптера.
3. Зарегистрировать `APIModel` с точной подписью, static/instance-признаком и обработчиком.
4. Реализовать поведение: результат, изменения памяти, проверки аргументов, ошибки и требуемое состояние между командами. Состояние должно корректно копироваться при разветвлении пути.
5. Добавить выбор нового профиля в `AngrLoader.load`; если нужен запуск через `main.py`, также включить имя в его CLI choices.
6. Проверить нормальные, граничные и ошибочные случаи модели, затем повторить конкретный и символьный запуск апплета.

Ориентиры в коде: `angr_integration/symdemo_api.py` для небольшого набора привязок; `angr_integration/javacard_api.py` для обработчиков и состояния; `angr_integration/loader.py` для подключения; `angr_integration/readiness.py` для проверки поддерживаемости.

Произвольный модуль профиля нельзя просто указать строкой в JSON: текущий загрузчик принимает зарегистрированные имена. Не заменяйте отсутствующее поведение константой «успех», не игнорируйте побочные эффекты и не отключайте readiness ради получения witness. Такой результат отвечал бы на другой вопрос о другой программе.

Если для нового API есть проверенная нативная реализация или наблюдения с карты, используйте их для проверки семантики. Сеанс не исполняет нативную прошивку автоматически.

## 16. Частые проблемы

| Сообщение или наблюдение | Что проверить |
| --- | --- |
| `failed loading unicornlib.dll/.so` | В проверенной среде это отключение необязательного Unicorn. Для CAP используется Soot backend. Ориентируйтесь также на последующий отчёт, `errors` и код завершения |
| `ModuleNotFoundError` для модуля проекта | Скрипты должны лежать рядом с `main.py`; проверьте, что проект содержит нужную версию модулей, а запускается нужный Python |
| Ошибка версии angr/pysoot | Установлены ли зависимости из закреплённых requirements именно в используемую venv |
| `Unknown Java Card API profile` | Имя есть в текущем `AngrLoader.load`; профиль действительно добавлен в эту копию проекта |
| `Unresolved symbols` | Внешние классы/методы, версия импорта, поля и подписи в `symbols.json` |
| `api_binding` | Имя или подпись не соответствует числовому ключу API |
| `Missing explicit interface signature` | Раздел `interface_signatures`, точный ключ и типы вызова |
| `Missing class declaration` | Декларация и иерархия внешнего класса в API-профиле; одного имени мало |
| `ExecutionNotReady` | Перечень неподдерживаемых операций/вызовов в отчёте; это ещё не результат поиска |
| `No bound process(APDU)` | Имена зарегистрированного класса и process, параметр APDU, связь с install |
| Ошибка регистрации при install | AID из Applet.cap, поддержанная перегрузка register и формат install-данных |
| `symbolic_api_argument` | Эта модель требует однозначного значения аргумента; нужно обоснованно ограничить сценарий или расширить модель |
| `found=0`, `active>0` | Поиск не завершён; отсутствие witness пока не доказывает недостижимость |
| `reached`, но `complete=false` | Свидетель есть, но часть других путей осталась необработанной или ошибочной |
| `reached`, а затем отказной SW | Цель была входом в метод; его дальнейшие проверки могут отклонить запрос |
| Цель не находится при `selecting=true` | Апплет может сразу возвращаться из process во время выбора |
| Изменился CAP hash | Пересобраны байткод/смещения; заново проверить символы и цель |
| Слишком много состояний | Уточнить вопрос и входную область, проверить циклы и длинные символические массивы; записать новые ограничения |

При ошибке сохраните полную диагностику с методом, Unit и CAP offset. Одного сообщения «скрипт не работает» недостаточно, чтобы отличить ошибку привязок от отсутствующей операции.

## Приложение A. inspect_applet.py

Сохраните следующий блок целиком в UTF-8 как `inspect_applet.py` рядом с `main.py`. Скрипт извлекает метаданные и создаёт черновик символов. Внешние имена и Java-имена внутренних методов он автоматически не восстанавливает.

```python
"""Copy this file beside main.py. Extract identities without guessing Java names."""
import argparse
from dataclasses import asdict
import hashlib
import json
from pathlib import Path
import re

from main import load_cap, extract_methods


def inventory(path):
    cap = load_cap(path)
    package = cap.header.package
    aid = package.aid.hex()
    version = [package.major_version, package.minor_version]
    prefix = f'{aid}@{version[0]}.{version[1]}'
    imports = [{'aid': p.aid.hex(), 'version': [p.major_version, p.minor_version]}
               for p in cap.import_componet.packages]  # Current project's field spelling.
    methods = []
    for method in extract_methods(cap):
        class_offset = int(re.fullmatch(r'[0-9a-f]+/class_(\d+)/method_\d+', method.name)[1])
        methods.append({'key': f'{prefix}:internal:t6:o{method.offset}',
                        'class_key': f'{prefix}:o{class_offset}',
                        'offset': method.offset, 'token': method.token,
                        'is_static': method.is_static, 'signature': asdict(method.signature),
                        'bytecode_length': len(method.bytecodes),
                        'handlers': [asdict(h) for h in method.exception_handlers]})
    applets = [{'aid': a.aid.hex(), 'install_key': f'{prefix}:internal:t6:o{a.install_method_offset}'}
               for a in cap.applet.applets]
    template = {'package_aid': aid, 'package_version': version, 'imports': imports,
                'class_names': {m['class_key']: 'REPLACE_WITH_JAVA_CLASS_NAME' for m in methods},
                'method_names': {m['key']: f"REPLACE_METHOD_AT_{m['offset']}" for m in methods},
                'field_names': {}, 'catch_types': {}, 'interface_signatures': {}}
    report = {'cap_sha256': hashlib.sha256(path.read_bytes()).hexdigest(),
              'cap_version': [cap.header.major_version, cap.header.minor_version],
              'package_aid': aid, 'package_version': version, 'imports': imports,
              'applets': applets, 'methods': methods,
              'constant_pool': [{'index': i, **asdict(entry)}
                                for i, entry in enumerate(cap.constant_pool.constant_pool)],
              'descriptor': asdict(cap.descriptor)}
    # Descriptor raw_types is a bytes payload, not an automatically decoded name table.
    report['descriptor']['types']['raw_types'] = cap.descriptor.types.raw_types.hex()
    return report, template


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('cap', type=Path)
    parser.add_argument('--output', type=Path, required=True)
    parser.add_argument('--symbols-template', type=Path, required=True)
    args = parser.parse_args()
    if args.symbols_template.exists():
        parser.error('Template already exists; choose another filename to preserve your edits')
    report, template = inventory(args.cap)
    for path, data in ((args.output, report), (args.symbols_template, template)):
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_text(json.dumps(data, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
    print(f"Package: {report['package_aid']} {report['package_version']}; methods={len(report['methods'])}")
    print('Fill the template from your JCA/API export data before executing the applet.')


if __name__ == '__main__':
    main()
```

## Приложение B. applet_lab.py

Сохраните следующий блок целиком в UTF-8 как `applet_lab.py` рядом с `main.py`. Загрузка, конкретный запуск и поиск используют один `analysis.json`. Скрипт ищет вход в метод, не произвольную Java-строку.

```python
"""Generic guide template. Copy beside main.py; all applet-specific data is in JSON.

Usage: python applet_lab.py load|concrete|find path/to/analysis.json
Paths in JSON are relative to that JSON file. No Java source is executed.
"""
import argparse
import hashlib
import json
from pathlib import Path


def positive_int(value, name):
    if type(value) is not int or value < 1:
        raise ValueError(f'{name} must be a positive integer')
    return value


def flag(command, name, default=False):
    value = command.get(name, default)
    if type(value) is not bool:
        raise ValueError(f'{name} must be a JSON boolean')
    return value


def byte(token, name, claripy, symbolic):
    if token == '*':
        if not symbolic:
            raise ValueError('Concrete/setup commands cannot contain *')
        return claripy.BVS(name, 8, explicit_name=True)
    if not isinstance(token, str) or not 1 <= len(token) <= 2:
        raise ValueError('Bytes must be hex strings 00..FF, or * for symbolic input')
    value = int(token, 16)
    if not 0 <= value <= 255:
        raise ValueError('Byte out of range')
    return claripy.BVV(value, 8)


def prepare(session, command, *, symbolic=False):
    c = session.loaded.dependencies.claripy
    fields = [command['cla'], command['ins'], command.get('p1', '00'), command.get('p2', '00')]
    header = [byte(token, name, c, symbolic) for token, name in zip(fields, ('CLA', 'INS', 'P1', 'P2'))]
    data = tuple(byte(token, f'DATA_{i:03d}', c, symbolic)
                 for i, token in enumerate(command.get('data', '').split()))
    if len(data) > 255:
        raise ValueError('Only short APDUs, at most 255 DATA bytes')
    state = session.prepare_command(header[1], header[2], header[3], data, cla=header[0],
                selecting=flag(command, 'selecting'), receive_length=command.get('receive_length'))
    packet = c.Concat(*header, c.BVV(len(data), 8), *data)
    return state, packet


def bits(value, width, claripy):
    if isinstance(value, int):
        return claripy.BVV(value & ((1 << width) - 1), width)
    if not isinstance(value, claripy.ast.BV) or value.size() < width:
        raise ValueError(f'Expected at least {width} bits for an API value')
    return value[width-1:0]


def summarize(result, packet, claripy):
    """One joint solver model per terminal path, including symbolic responses/SW."""
    rows = []
    input_length = packet.size() // 8
    for end in result.completed:
        response = [bits(v, 8, claripy) for v in end.javacard.response]
        sw = bits(end.javacard.status, 16, claripy)
        # Never evaluate different packet/output bytes using unrelated models.
        joint = claripy.Concat(packet, *response, sw)
        raw = end.solver.eval(joint, cast_to=bytes)
        rows.append({'one_model': {'packet_without_le_hex': raw[:input_length].hex(' ').upper(),
                                   'response_hex': raw[input_length:-2].hex(' ').upper(),
                                   'sw': raw[-2:].hex().upper()},
                     'sw_expression': str(sw), 'response_expressions': [str(v) for v in response],
                     'sw_is_unique': len(end.solver.eval_upto(sw, 2)) == 1,
                     'constraints': [str(v) for v in end.solver.constraints]})
    return {'completed': rows, 'active': len(result.active),
            'errors': [str(record.error) for record in result.errored]}


def finished(result):
    return not result['active'] and not result['errors']


def load_program(config, directory):
    from main import (load_cap, extract_methods, load_symbols, verify_methods, build_cfgs,
                      build_jcvm_ir, build_jvm_like_ir, build_soot_ir, build_pysoot_model,
                      load_angr_program)
    cap_path = (directory / config['cap']).resolve()
    symbols_path = (directory / config['symbols']).resolve()
    actual = hashlib.sha256(cap_path.read_bytes()).hexdigest()
    if config.get('cap_sha256') and actual != config['cap_sha256'].lower():
        raise ValueError('CAP hash changed; review symbols and target_key for the new build')
    cap, symbols = load_cap(cap_path), load_symbols(symbols_path)
    if any('REPLACE_' in name for mapping in (symbols.class_names, symbols.method_names,
                                              symbols.field_names) for name in mapping.values()):
        raise ValueError('Fill all symbol template placeholders before loading')
    methods = extract_methods(cap)
    verify_methods(methods)
    jcvm = build_jcvm_ir(cap, methods, build_cfgs(methods), interface_signatures=symbols.interface_signatures)
    program = build_pysoot_model(cap, build_soot_ir(build_jvm_like_ir(jcvm), symbols), symbols)
    return load_angr_program(program, api_profile=config['api_profile']), actual


def install_and_prepare(loaded, config):
    from angr_integration.javacard_session import JavaCardSession
    session = JavaCardSession(loaded)
    session.install(max_steps=positive_int(config.get('install_steps', 500), 'install_steps'))
    steps = positive_int(config.get('max_steps', 500), 'max_steps')
    c = loaded.dependencies.claripy
    setup_log = []
    for command in config.get('setup', []):
        initial, packet = prepare(session, command)
        result = session.run(initial, max_steps=steps)
        summary = summarize(result, packet, c)
        if not finished(summary) or len(result.completed) != 1:
            raise RuntimeError(f'No unique completed setup state: {summary}')
        end = result.completed[0]
        expected_sw = int(command['expected_sw'], 16)  # Explicit for every setup command.
        if not 0 <= expected_sw <= 65535:
            raise ValueError('expected_sw must be in 0000..FFFF')
        sw = bits(end.javacard.status, 16, c)
        if end.solver.satisfiable(extra_constraints=[sw != expected_sw]):
            raise RuntimeError(f'Unexpected setup SW: {summary}')
        session.choose(end)
        setup_log.append(summary)
    return session, setup_log


def search_to_entry(loaded, initial, target, steps):
    manager = loaded.project.factory.simgr(initial)
    rounds = 0
    while True:
        manager.move(from_stash='active', to_stash='found', filter_func=lambda s: s.addr == target)
        if not manager.active or rounds >= steps:
            break
        manager.step()
        rounds += 1
    found = manager.stashes.get('found', [])
    other = {name: len(states) for name, states in manager.stashes.items()
             if states and name not in ('found', 'active', 'deadended', 'unsat')}
    errors = [str(record.error) for record in manager.errored]
    for end in manager.deadended:
        if end.javacard.transaction is not None and end.javacard.exception is None:
            errors.append('uncommitted_transaction: a non-target path returned with an open transaction')
    complete = not manager.active and not errors and not other
    stats = {'found': len(found), 'deadended': len(manager.deadended),
             'active': len(manager.active), 'errors': errors, 'other_stashes': other,
             'step_rounds': rounds, 'max_steps': steps, 'complete': complete}
    return found, stats


def find_target(session, config):
    loaded, c = session.loaded, session.loaded.dependencies.claripy
    steps = positive_int(config.get('max_steps', 500), 'max_steps')
    initial, packet = prepare(session, config['input'], symbolic=True)
    target = loaded.method_address(config['target_key'])
    found, stats = search_to_entry(loaded, initial, target, steps)
    complete = stats['complete']
    report = {'verdict': 'reached' if found else ('unreachable_in_model' if complete else 'unknown'),
              'target_key': config['target_key'], 'target_address': str(target),
              'context': config['input'], 'Lc': (packet.size() // 8) - 5,
              'search': stats,
              'paths': []}
    for hit in found:
        witness = hit.solver.min(packet).to_bytes(packet.size() // 8, 'big')
        continuation = summarize(session.run(hit.copy(), max_steps=steps), packet, c)
        # Recreate the final command from the same installed/setup state.
        replay_command = {name: f'{value:02X}' for name, value in zip(('cla','ins','p1','p2'), witness[:4])}
        replay_command.update(data=witness[5:].hex(' '),
                              selecting=flag(config['input'], 'selecting'),
                              receive_length=config['input'].get('receive_length'))
        replay_state, replay_packet = prepare(session, replay_command)
        replay_hits, replay_search = search_to_entry(loaded, replay_state.copy(), target, steps)
        replay = summarize(session.run(replay_state, max_steps=steps), replay_packet, c)
        replay['target_reached'] = bool(replay_hits)
        replay['search'] = replay_search
        report['paths'].append({'constraints': [str(v) for v in hit.solver.constraints],
                                'packet_without_le_hex': witness.hex(' ').upper(),
                                'continuation': continuation, 'replay': replay})
    ok = complete and all(finished(p['continuation']) and finished(p['replay'])
                          and p['replay']['target_reached'] and p['replay']['search']['complete']
                          for p in report['paths'])
    return report, ok


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument('mode', choices=('load', 'concrete', 'find'))
    parser.add_argument('config', type=Path)
    args = parser.parse_args()
    config = json.loads(args.config.read_text(encoding='utf-8-sig'))
    directory = args.config.resolve().parent
    loaded, cap_hash = load_program(config, directory)
    output = (directory / config['output']).resolve()
    output.mkdir(parents=True, exist_ok=True)
    loaded.export(output / 'loader')
    report = {'mode': args.mode, 'cap_sha256': cap_hash, 'config': config,
              'symbols_sha256': hashlib.sha256((directory / config['symbols']).read_bytes()).hexdigest(),
              'api_profile': loaded.to_dict()['api_profile'],
              'versions': loaded.to_dict()['versions']}
    ok = True
    if args.mode != 'load':
        if loaded.program.unresolved_symbols:
            raise ValueError(f'Unresolved symbols: {loaded.program.unresolved_symbols}')
        session, report['setup'] = install_and_prepare(loaded, config)
        if args.mode == 'concrete':
            initial, packet = prepare(session, config['baseline'])
            steps = positive_int(config.get('max_steps', 500), 'max_steps')
            report['result'] = summarize(session.run(initial, max_steps=steps), packet, loaded.dependencies.claripy)
            ok = finished(report['result'])
        else:
            report['result'], ok = find_target(session, config)
    path = output / (args.mode + '.json')
    path.write_text(json.dumps(report, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
    if args.mode == 'find':
        print(report['result']['verdict'], report['result']['search'])
        for row in report['result']['paths']:
            print('Packet without Le:', row['packet_without_le_hex'])
    elif args.mode == 'concrete':
        print(json.dumps(report['result'], ensure_ascii=False, indent=2))
    else:
        print('Loaded only: inspect loader/load_report.txt before execution')
    print('Report:', path)
    return 0 if ok else 2
```
